# F1 — a generative model of the Delta League score as a function of the weight edit

Agent F1 (mathematician). Code in this directory: `f1_tf.py` (teacher forcing through the ORIGINAL base model; stores
what is needed to re-run the exact vLLM sampler under any edit of the family), `sampler.py` (exact sampler
counterfactuals: presence 1.5 on generated tokens -> T=1 -> top-k 20 -> top-p 0.95), `hazard.py` / `predict.py` /
`predict_xf3s.py` (trace-level survival model and score predictor), `gateway.py` (closing-mechanism statistics),
`geom.py` (embedding geometry), `f1_tf_answer.py` + `eos_analysis.py` (answer-phase / EOS lever), `build_lda.py`
(builder for a discriminant-direction edit of the `</think>` row), `xf3s_base/` (base embeddings + xf3s layer edits, used
to teacher-force b8af1dbc traces with the sampler parametrised relative to the original rows).
All proxy numbers are advisory (320 public prompts, deterministic: `c_new` and `r_newleader` are bit-identical);
private numbers are the leaderboard values quoted in the brief.

Data: 55 traces generated by a9340e14 (`c_new`, stratified over bench x {correct, wrong, truncated}, re-weighted to the
proxy population; 289k teacher-forced positions), 19 base-generated traces (`c_base`), 49 traces generated by
b8af1dbc (`c_xf3s`), answer phases of 5 `c_new` generations, and the per-item results of `c_base`, `c_leader`, `c_new`,
`c_think15`, `c_xf3s`, `a3_new_g13`.

## 1. Notation and the exact sampler

Tied embeddings: logit of token i at step t is `z_i(t) = h_t . e_i`, with `h_t = (1+w) * x_t / rms(x_t)` the final-norm
output at the BASE gain; `m_t = h_t . mu` (mu = mean embedding row) is the mean logit over the vocabulary.
Edit theta = (g, {s_i}, mode, c, {b_i}):

    z'_i     = g * s_i * z_i                      pure scaling (`scale_tokens`)
    z'_i     = g * (s_i z_i + (1-s_i) m_t)        mean interpolation (`tokens`, mode mean; old leader)
    z'_close = g * c * z_close                    (`close_gain`)
    z'_i    += g * b_i * m_t / |mu|^2 = 12.9 g b_i m_t      (`bias`: NOT a constant, it is proportional to m_t)
    z'_j     = g * z_j                            every other token.

vLLM then forms `l_i = z'_i - 1.5 [i already generated]`, softmax at T=1, top-k 20, top-p 0.95. `sampler.py`
reproduces this from the stored top-64 raw logits + 40 watch rows. Calibration on the generating edit (a9340e14):
sum_t p(</think>) = 3.87 vs 4 actual closes (first 6 traces; 0.98 per closed trace on all 55), expected hedge-13 tokens
170.8 vs 166 actual, expected Wait/Hmm 0.0 vs 0 actual, 0.06% of generated tokens fall outside the recomputed nucleus.

Everything reduces to a two-token competition: P(i beats the top other token o) = sigma( g (z'_i/g - z_o) +
1.5 ([o seen] - [i seen]) ). Gain multiplies logit differences but NOT the presence penalty, so the effective presence
penalty is 1.5/g in base units (1.07 at g=1.4, 0.90 at g=1.667). Scales: competitive logits z_max 22-34 (median 27.6);
m_t in [-5, +1] (median -2.4); |mu|^2 = 0.0774; mean (1+w) = 4.31.

## 2. Lever 1 — hedge rows: it is annihilation, and the mode does not matter

At the 996 positions (13 per 1k tokens) where the base model gives Wait/Hmm probability > 0.3, z_h = 23.5 +- 1.8 and
z_max = 24.0 (the hedge IS the argmax half of the time: base P = 0.52).

| edit | logit shift (g=1) | x g=1.4 | residual P(Wait/Hmm) |
|---|---|---|---|
| scale 0.5 (a9340e14) | -11.7 nats | -16.4 | 0.0000 |
| scale 0.4 | -14.1 | -19.7 | 0.0000 |
| scale 0.6 | -9.4 | -13.2 | 0.0000 |
| mean 0.6 (ab592312) | -10.0 | -14.0 | 0.0000 |
| scale 0.8 | -4.7 | -6.6 | 0.0009 |
| scale 0.93 | -1.6 | -2.3 | 0.056 |

Pure scaling vs mean interpolation differ by g (1-s) m_t = -1.3 nats at s=0.6: irrelevant next to -10. For s <= 0.6
both modes ANNIHILATE the row wherever it is competitive (z_h > 0 always holds there, so "scaling" is always a
suppression; it never boosts). The exact s and the mode are irrelevant; only the SET of rows matters (leaderboard:
0.4-scale on 7 rows 24.6, 0.4 on more rows 22.4, 0.6-mean on 11 rows + gain 28.2). Partial damping of other tokens
(a2's 0.93-0.96) lives in the only informative range: s = 0.93 removes 1.6 nats and keeps 5.6% of the probability.

Where does the Wait mass go? Under scale-0.5 at former-Wait positions: 79% to ordinary continuations (` Let`, ` If`,
` This`, ` So`), 18% to substitute hedges (` But`, ` However`), 2.7% to remaining hedge-13 rows, 0.0% to `</think>`
(r = z_close/z_max is 0.16 there). The hedge lever has no first-order effect on closing; it works through trace
dynamics only (fewer re-check cycles -> the finished state is reached before 8192). a2's text analysis of `c_new`
truncations (59% re-check cycles now started by If/So/But/This/Then/Maybe) is this substitution.

## 3. Lever 2 — `</think>` row: a threshold on r = z_close / z_max, and why it is a knife-edge

Closing only happens at a "gateway": the position right after a lone `\n` (token 198) ending a sentence; the top
competitor is an indentation token (`'   '`, `'       '`; 75% of cases) and is always `seen` (34/35 observed closes).

    P(close at a gateway) = sigma( g z_max (c r - 1) + 1.5 ),   r*(c,g) = (1 - 1.5/(g z_max)) / c.

At z_max = 29, g = 1.4: r* = 0.963 (c=1), 0.84 (1.15), 0.80 (1.2), 0.77 (1.25), 0.74 (1.3), 0.71 (1.35), 0.69 (1.4),
0.64 (1.5). Observed r at closes: a9340e14 median 0.769 (range 0.72-0.88), margin z_close - z_other = -6.2 nats, base
p_close ~ 0.001 there: EVERY close of the current leaders is manufactured by c. Base natural closes: r = 0.89-0.93,
margin -2 to -3, p = 0.18-0.41 per gateway.

Tail law of r over all non-close positions (289k positions), per 1k tokens: N(r>0.5) = 23.7, N(>0.55) = 11.9,
N(>0.6) = 4.3, N(>0.65) = 1.03, N(>0.7) = 0.135, N(>0.75) = 0.003, N(>0.8) = 0. In the working range
N(x) ~ 4.3 exp(-(x-0.6)/kappa), kappa = 0.023: EACH +0.05 OF THRESHOLD IS A FACTOR ~8 IN PREMATURE HAZARD; in c:
d(sampler logit)/d ln c = g z_close = 42 nats (a3's number), so +5% in c = +2 nats = x7 premature hazard.
Gateways: 46/1k tokens; r > 0.6 at 8% of them, r > 0.7 at 0.6% (closed traces) / 0.04% (truncated traces);
truncated traces never reach r > 0.72 in 8192 tokens — they cannot be closed by any c that does not also fire on
unfinished gateways.

Two populations of manufactured closes:
* finished-state capture: once the model has written its wrap-up line, gateways with r = 0.72-0.93 recur every
  60-300 tokens over 1.6-3.6k tokens (base traces: 5-8 such gateways before the natural close at r~0.9). Capture per
  finished gateway (r = 0.76, z_max 29, g 1.4): 0.04 (c 1.15), 0.15 (1.2), 0.45 (1.25), 0.80 (1.3), 0.95 (1.35), 0.99 (1.4).
* premature hazard: unfinished gateways with r in 0.6-0.72 (4/1k tokens). The single most dangerous position is t=0,
  right after `<think>\n`: r = 0.657 +- 0.028 and nothing is `seen`. P(skip thinking) = p_close(t=0):
  g=1.4: 0.003 (c 1.3), 0.023 (1.35), 0.085 (1.4), 0.21 (1.45), 0.40 (1.5); g=1.0: 0.019 (1.3), 0.059 (1.35),
  0.134 (1.4), 0.41 (1.5). This is the 41% "skip thinking" mode of 0ffb5aef (proxy closed-length 10th pct 389 tokens).

So the multiplicative edit is conditional on r, but the premature band (0.6-0.72) and the legit band (0.72-0.9) are
~3 nats apart at z_max 29 and the T=1 sampler smears by 1-2 nats. The usable range of c is 1.25-1.35: below it finished
traces are not captured, above it the premature hazard grows x7 per +5%. A copy at c +- 0.05 moves the private score by
several points; that is the knife-edge the owner called out. The `bias` lever cannot sharpen it: at legit closes
m_t = -0.59 +- 0.69 vs -0.88 +- 0.65 at risk gateways (no discrimination), and (c, b) grids move premature and legit
mass together (Section 7). z_max is slightly LOWER at legit closes (29.2) than at risk gateways (31.8), so a constant
bias would not help either.

## 4. Lever 3 — global gain g

1. g sharpens every competition without changing its sign. `</think>` is always second at natural gateways
   (margin -2 to -7), so g alone LOWERS natural closing: sigma(g m + 1.5) at m = -2.5 is 0.27 (g 1), 0.12 (1.4),
   0.07 (1.667) -> truncation rises (d17ce35f 0.826), and only the easiest traces close (acc|closed 98.9%).
2. The effective presence penalty falls to 1.5/g: fewer loop-breaking events -> verbatim grooves (a2: 16% of ab592312
   truncations, 10% of a9340e14's).
3. With c >= 1.3, `</think>` IS argmax at finished gateways and g now amplifies closing; at t=0 c z_close < z_max for
   c <= 1.5 so higher g REDUCES skip-thinking (c=1.4: 0.134 at g=1 -> 0.072 at g=1.55). Gain only helps closing in
   combination with c, and the combination is self-limiting in the premature direction. Along a9340e14 traces, g has
   almost no first-order effect on the hedge rate (56.5 -> 52.2 expected Wait/Hmm per trace-set at g 1 -> 1.4).

## 5. Interactions — why the combos work and the singles do not

* dampen alone (22-25): removes ~56 Wait/Hmm re-check triggers per 8k trace, but 18% substitute, and the finished
  state still dithers 1.6-3.6k tokens before a natural r~0.9 close.
* gain alone: 1.25 does nothing (19.0); 1.667 adds truncation (17.2) by effects 4.1 + 4.2.
* close x1.5 alone (17.6 private but 38.1 raw proxy): r* = 0.64 -> 41% skip-thinking + 0.7/1k premature hazard; the
  closed set is 56% of items but acc|closed 31%. The raw proxy scores the long answer-phase rambling that follows a
  premature close (math_verify on the whole answer: 0.19 on items closed only by x1.5; 0.69 on <1000-token quick closes
  of easy items), the server does not: on private, the 31 points of extra closed items added ~0 (a0_private ~ 0-0.1).
  The strict proxy (a6) removes this: c_think15 strict is far below raw.
* dampen + gain (28.2): fewer cycles -> more traces finished before 8192; g sharpens the now hedge-free continuations.
* dampen + gain + close 1.3 (31.4): c cuts the dithering phase (first r>0.74 gateway instead of the natural r~0.9 one,
  saving 1.6-3.6k tokens) and converts "finished but unclosed at 8192" into closed; skip 0.3%, premature 0.01/1k.
  Side effect: failures move into answer-phase overflow (a2: 15% of `c_new` truncations; 27 rows).
* + doubt-direction projection (36.0, b8af1dbc): removes the re-check cycles at the representation level (a2: re-check
  3% of truncations, Wait vocabulary dead), so far more traces reach the finished state and are captured by c=1.3:
  never-closed 150 -> 60 rows on the proxy. The costs appear exactly where the model says they must: more premature
  closes (overflow 24 -> 41 rows, median thinking before the premature close 1076 tokens, answers loop, score 2.4%),
  wrong normal closes (acc|normal 74.6 -> 56.3%: harder items now close), and verbatim grooves (33% of truncations)
  because the escape vocabulary is gone.

## 6. Macro model (trace level)

For a trace generated under theta0 and teacher-forced through base (or xf3s_base), under candidate theta:
pi_t = exact sampler P(</think> at t); S_t = prod_{u<t}(1 - pi_u); P(close at t) = pi_t S_t.
t < A is PREMATURE (A = first position where the reference answer appears in the thinking), else LEGIT.
Premature close -> a0 (0.31 raw proxy; ~0.05 private / strict; on b8af1dbc it is an answer-phase overflow, 0).
Legit close in a closed trace -> its observed correctness; in a truncated trace -> a_L (0.7 raw; 0.5 strict).
Remaining mass S_end: finished traces keep meeting finished gateways every G_fin = 100 tokens (base traces: 60-300),
each closing with p_fin(theta) = weighted mean pi_theta at the observed close positions; stuck traces stay truncated.
Weights re-balance the stratified sample to the population of the generating run.

Validation (first-order model from a9340e14 traces, raw-proxy a0):
* self-prediction a9340e14: acc 35.5 / trunc 0.467 vs actual 33.4 / 0.553; the 0.086 gap in truncation is exactly the
  answer-overflow share (27/320 = 0.084) that the thinking-phase model cannot see -> added as a regime in predict_xf3s.
* a3_new_g13 (stack with g 1.3): predicted +0.1 raw / -0.004 trunc vs stack; actual +2.2 raw (35.6), -0.016 trunc,
  skip 4 -> 9 rows (model: t=0 skip 0.003 -> 0.005). Within the proxy's chaos noise (paired SE ~2.1 strict).
* a3_new_g155 (stack with g 1.55): predicted -0.3 strict-like; actual strict 31.9 vs 33.1 (-1.2), overflow 24 -> 33 rows.
* f1_h13c13 (stack + Maybe/Actually/Alternatively 0.5): predicted +2.0 strict-like; actual raw 36.9 (+3.4), strict 35.0 (+1.9),
  never 150 -> 140. Right size, below a1's +3.5 screen.
* c_think15 (c 1.5, g 1): predicted raw 38.4 vs actual 38.1; the thinking-phase model puts trunc at 0.07 while the run
  shows 0.44 — again the answer-overflow regime (closes early, rambles to 8192).
* Backward direction (predicting base/ab592312 from a9340e14 traces, or a9340e14 from base traces) fails by design:
  from 6 base traces the stack is predicted at trunc 0.89 vs 0.55 actual — the first-order model sees only the
  closes available on the observed trajectory; the hedge/doubt levers act by changing the trajectory. The model is a
  forward model for edits that add closing hazard (c, g) on a given parent, which is what the remaining decisions are.

## 8. Orthogonal mechanisms examined

* `bias` along mu: no discriminating power (Section 3); dead end.
* EOS / answer-length lever (`<|im_end|>` 248044, `<|endoftext|>` 248046 rows): inside thinking EOS is never in the
  nucleus (r_eos max 0.53; expected EOS emissions in 43 traces at x1.5: 0.002), so it is safe; but in the answer phases
  of overflow generations the stop token is never competitive either (r <= 0.56, in the top-8 at 0.1% of positions),
  because the answer phase is thinking in disguise. Boosting EOS only shortens normal answers. Dead end: overflow must
  be fixed upstream (fewer premature closes, i.e. lower c or a better close discriminator).
* Hidden-state discriminant for the `</think>` row (`build_lda.py`): a shrinkage-LDA direction in final-norm space
  separates legit close positions from risk gateways (r 0.58-0.72) with leave-one-trace-out AUC 0.985 (34 positives,
  1711 negatives), vs AUC 0.83 for z_close itself; positives' 10th percentile projection 6.2 vs negatives' 99th 7.9.
  Adding delta * d_hat to e_close would move the legit/premature separation from ~3 nats to ~6-8 nats, i.e. flatten the
  knife-edge. Risk: the tied row is also the INPUT embedding of `</think>` (|e_close| = 0.57; delta ~ 0.4-0.5 needed),
  so the answer phase sees a different token embedding; must be screened on strict + overflow. Not submitted (no run).
* Verbatim grooves (33% of b8af1dbc truncations): at groove line starts a2 measures p(top1) = 1.000, non-top mass
  0.002 -> a logit gap of >= 6 nats x g. Gain re-tuning cannot unlock them (g 0.95 relative changes the gap by 5%);
  only a representation-level edit (stuck direction) or a repetition-sensitive mechanism can. Out of my family.
